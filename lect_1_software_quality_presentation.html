Класифікація метрик якості

За об'єктом вимірювання

  • Метрики продукту — характеристики коду (складність, розмір)
  • Метрики процесу — ефективність розробки (швидкість, продуктивність)
  • Метрики проєкту — управлінські показники (вартість, термін)

За способом отримання

  • Прямі метрики — безпосереднє вимірювання (LOC, кількість дефектів)
  • Непрямі метрики — розраховані показники (щільність дефектів, складність)

Основні групи метрик:

📏 Метрики розміру LOC, SLOC, Function Points
🔀 Метрики складності Цикломатична складність, Halstead
🔗 Метрики структури Зв'язаність, зчеплення
⚡ Метрики надійності MTTF, MTBF, щільність дефектів

Цикломатична складність McCabe

Визначення

Кількість лінійно незалежних шляхів через програму (граф потоку керування)

Формули розрахунку:

V(G) = E - N + 2P

де E — ребра, N — вершини, P — компоненти зв'язності

V(G) = π + 1

де π — кількість предикатів (умов розгалуження)

Інтерпретація значень:

Значення V(G) Оцінка складності Ризик
1-10 Простий код Низький
11-20 Помірна складність Середній
21-50 Складний код Високий
>50 Дуже складний Критичний

Зв'язаність та зчеплення модулів

Зв'язаність (Coupling) ⬇️ Менше = Краще

Ступінь взаємозалежності між модулями

Види (від гіршого до кращого):
  1. Змістова зв'язаність
  2. Зовнішня зв'язаність
  3. Контрольна зв'язаність
  4. За даними
  5. За повідомленням ✓
Метрики:
  • CBO (Coupling Between Objects)
  • RFC (Response For a Class)

Зчеплення (Cohesion) ⬆️ Більше = Краще

Ступінь зв'язку елементів всередині модуля

Види (від гіршого до кращого):
  1. Випадкове зчеплення
  2. Логічне зчеплення
  3. Часове зчеплення
  4. Процедурне зчеплення
  5. Комунікативне зчеплення
  6. Послідовне зчеплення
  7. Функціональне зчеплення ✓
Метрика:
  • LCOM (Lack of Cohesion of Methods)
  • Низький LCOM = високе зчеплення

🎯 Ідеальна архітектура

Низька зв'язаність + Високе зчеплення

Метрики надійності ПЗ

Щільність дефектів (DD)
DD = Кількість дефектів / KLOC

Типові значення: 1-25 дефектів/KLOC

MTTF (Mean Time To Failure)
MTTF = Загальний час / Кількість відмов

Середній час до відмови

MTBF (Mean Time Between Failures)
MTBF = MTTF + MTTR

MTTR — час відновлення

Коефіцієнт готовності
A = MTTF / (MTTF + MTTR) × 100%

Відсоток часу працездатності

📊 Приклад розрахунку

Дано: Модуль 850 LOC, 4 дефекти, 2000 год роботи, 2 відмови

DD = 4 / 0.85 = 4.7 дефектів/KLOC
MTTF = 2000 / 2 = 1000 годин

Метрики покриття коду (Code Coverage)

Statement Coverage

Відсоток виконаних інструкцій

SC = (Виконані / Загальні) × 100%

Найпростіша метрика покриття

Branch Coverage

Відсоток перевірених гілок

BC = (Перевірені гілки / Всі гілки) × 100%

Перевіряє умови if/else

Path Coverage

Відсоток пройдених шляхів

PC = (Пройдені шляхи / Всі шляхи) × 100%

Найсуворіша метрика

Condition Coverage

Відсоток перевірених умов

CC = (Перевірені умови / Всі умови) × 100%

Перевіряє true/false для кожної умови

📈 Рекомендовані рівні покриття

  • Критичні системи: 90-100%
  • Комерційні додатки: 70-85%
  • Внутрішні інструменти: 60-70%

Технічний борг (Technical Debt)

Визначення

Додаткові зусилля, необхідні для виправлення субоптимальних рішень у коді.

Розрахунок технічного боргу:

TD = Час на виправлення × Вартість години розробника
TDR = Технічний борг / Вартість розробки

Коефіцієнт технічного боргу (рекомендовано ≤ 5%)

⚠️ Причини виникнення

  • Тиск дедлайнів
  • Недостатня документація
  • Відсутність рефакторингу
  • Застарілі технології
  • Неоптимальні рішення

✓ Методи зменшення

  • Регулярний рефакторинг
  • Code review
  • Автоматизоване тестування
  • Дотримання стандартів
  • Планування часу на якість

CMMI — Capability Maturity Model Integration

Мета CMMI

Оцінка та покращення процесів розробки ПЗ на організаційному рівні

П'ять рівнів зрілості:

1
Початковий (Initial)

Хаотичні процеси, непередбачувані результати

2
Керований (Managed)

Плановані проєкти, процеси повторюються

3
Визначений (Defined)

Стандартизовані процеси, проактивне управління

4
Кількісно керований (Quantitatively Managed)

Процеси вимірюються, прогнозовані результати

5
Оптимізований (Optimizing)

Постійне покращення, організаційне навчання

Висновки

🎯 Ключові положення

1. Багатовимірність якості

Якість ПЗ — це комплексна характеристика, що еволюціонувала від простих моделей McCall до сучасних стандартів ISO/IEC 25010.

2. Структурований підхід

Моделі якості (McCall, Boehm, ISO) забезпечують систематичний підхід до оцінювання якості ПЗ на всіх етапах розробки.

3. Безпека як пріоритет

ISO/IEC 25010 включає безпеку як окрему характеристику якості, підкреслюючи її критичну важливість у сучасному світі.

4. Вимірюваність якості

Метрики якості (складність, зв'язаність, надійність) дозволяють кількісно оцінити стан ПЗ та приймати обґрунтовані рішення.

5. Процесна зрілість

CMMI забезпечує фреймворк для систематичного покращення процесів розробки на організаційному рівні.

6. Автоматизація обов'язкова

Використання інструментів статичного аналізу та автоматизованого тестування є необхідною практикою сучасної розробки.
